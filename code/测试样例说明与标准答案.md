# 测试样例说明与标准答案

这份目录用于给你的软件度量平台做回归测试。下面的组织顺序，已经按你前端左侧菜单从上到下排列，方便你逐项对照。

## 1. 测试目录说明

- `java-metric-sample/`
  - 一组专门用于测试 `LoC / 圈复杂度 / CK / LK` 的 Java 文件
- `model-files/academic-model.xml`
  - 一组用于测试 `.xml` 模型文件解析的 UML 风格结构化文件
- `model-files/academic-model.xmi`
  - 一组用于测试 `.xmi` 模型文件解析的 UML 风格结构化文件
- `model-files/academic-model.oom`
  - 一组用于测试 `.oom` 模型文件解析的 XML 风格结构化文件
- `project-assist-sample/`
  - 一组用于测试“功能点项目预填辅助”的 Java 文件
- `project-assist-sample-basic/`
  - 一组用于测试“功能点项目预填辅助（基础 CRUD 场景）”的 Java 文件
- `project-assist-sample-admin/`
  - 一组用于测试“功能点项目预填辅助（管理/报表重场景）”的 Java 文件
- `function-point-models/`
  - 一组用于测试“功能点基于数据流图/用例图模型文件直接识别”的复杂 XML / XMI / OOM 文件
- `project-assist-models/usecase-assist.xml`
  - 用于测试“用例点项目预填辅助”的 XML 用例模型
- `project-assist-models/usecase-assist.xmi`
  - 用于测试“用例点项目预填辅助”的 XMI 用例模型
- `project-assist-models/usecase-assist.oom`
  - 用于测试“用例点项目预填辅助”的 OOM 用例模型
- `project-assist-models/usecase-basic.xml`
  - 用于测试“用例点项目预填辅助（轻量场景）”的 XML 用例模型
- `project-assist-models/usecase-admin-heavy.xmi`
  - 用于测试“用例点项目预填辅助（管理重场景）”的 XMI 用例模型
- `edge-java-sample/`
  - 一组用于测试 `注释行 / 空行 / switch / 逻辑运算 / 三目运算` 的边界 Java 文件
- `api-payloads/`
  - 用于直接调用后端接口验证 `功能点 / 用例点 / 估算分析` 的 JSON 请求体

建议做法：

1. Java 样例单独建一个项目上传。
2. 三个模型文件可分别单独建项目上传，便于核对单文件答案。
3. `project-assist-sample/`、`function-point-models/` 和 `project-assist-models/` 建议分别单独建项目。
4. 功能点、用例点页面现在点击 `计算` 会先按文件重新识别，再做最终计算。
5. 需要验证手工修正时，再按本文后半部分的输入修改局部字段。
5. 不要把 Java 样例和模型文件全部混在一个项目里做第一次验算，否则结果会叠加，不方便比对。

## 10. 智能分析

智能分析不是固定唯一数值答案，它更适合做“结果是否合理”的校验。

### 10.1 建议核对点

如果你已经先完成：

1. 代码行度量
2. 控制流图度量
3. 面向对象度量
4. 功能点 / 用例点 / 估算分析

那么智能分析里至少应该能体现这些趋势：

- `EnrollmentService` 应更容易被识别为重点风险类
- `SplitStorage` 应体现出内聚性问题
- `GraduateStudent` 应体现继承层次较深
- 如果做了估算，报告中应能引用规模、工期、成本或人员相关信息

### 10.2 验证方式

这一项主要看：

1. 能否正常生成分析结果
2. 结果中有没有结合前面各模块的数据
3. 风险判断和改进建议是否与前面模块结果一致

## 12. 使用提醒

1. 旧结果不会自动刷新，修改代码后要重新点击分析。
2. 模型文件如果多个一起上传，摘要结果会累加。
3. 功能点、用例点、估算分析依赖用户输入，不是从代码里自动推导。
